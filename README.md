# Документация Asmy

Пользовательское руководство [Admire Server Manager](https://docs.asmy.pro):
установка панели, домены и Caddy, Docker, файлы, пользователи и обслуживание.
Исходники статей находятся в `content/`, иллюстрации — в `public/images/`.

## Сборка документации

Сайт использует Docus 5 как Nuxt layer вместо прежнего `@nuxt-themes/docus`.
Контент остаётся в `content/`, ресурсы — в `public/`. Версии закреплены в
`package.json`, `pnpm-lock.yaml` и Dockerfile. Для локальной работы использовать
Node 24 LTS и pnpm из `packageManager`:

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm generate
```

`generate` создаёт `.output/public`, который Docker image обслуживает через Nginx.
Для интерактивной локальной проверки запустить `pnpm dev`. На Windows проверены
поиск, переходы между статьями и изменение Markdown через HMR; static image
проверен отдельно. Локальные установки, запуски и проверки агентам разрешены
владельцем; публикация и удалённый deploy требуют отдельного запроса.
`nitro.prerender.autoSubfolderIndex: true` необходим для сохранения адресов без
`.html`: каждый route получает свой `index.html`. `failOnError: true` запрещает
публикацию с ошибкой prerender. На Windows с junction Nuxt проверки запускать из
канонического пути checkout: генерация относительных module paths иначе может
ломать ESLint/prerender imports.

Главная страница находится в `content/index.md`: стандартные `u-page-hero`,
`u-page-section`, `u-page-grid` и `u-page-card` задают контейнеры, карточки
задач и ссылки на установку и обслуживание. Собственные компоненты и отдельная тема не нужны.
Навигация разделов задаётся `.navigation.yml`. Старые Pinceau tokens и MDC `list`
заменены настройками Nuxt UI и обычными Markdown списками. Автоматическая OG
генерация отключена: сохранена прежняя глобальная картинка `https://asmy.pro/og_image.jpg`.
Ссылка «Редактировать эту страницу» удалена патчем Docus: документацию ведёт
команда проекта, приглашение читателей к редактированию не требуется. Ссылка
«Сообщить о проблеме» и обычные ссылки на GitHub сохранены. Отдельные стили
переноса для прежнего блока из двух ссылок больше не нужны.

## Ограничения зависимостей

TypeScript оставлен на совместимой с Vue tooling ветке 6. Патч Docus исправляет
augmentation `AppConfig` в `@nuxt/schema`; эту часть удалить после upstream
исправления. Тот же patch удаляет предложение редактировать страницу; эту
продуктовую настройку сохранять при обновлении Docus.
Override `@nuxt/devtools>simple-git` и однострочный patch импорта Devtools позволяют
использовать исправленную ветку Git adapter. Override `fontless>esbuild` устраняет
advisory Windows development server. После поддержки исправленных версий upstream
соответствующие overrides/patches нужно удалить.

`pnpm peers check` сообщает о двух optional peer требованиях `unctx@3.0.1`
(`oxc-parser >=0.140`, `unplugin ^3.3`) к версиям родительской цепочки Nuxt.
Generate, typecheck и browser smoke проходят; принудительно заменять общие parser
и plugin версии других Nuxt-пакетов ради подавления этого предупреждения не нужно.

Audit сохраняет два high advisory без patched release в build/dev цепочке:
[node-forge](https://github.com/advisories/GHSA-86w9-cpqp-85rv) и
[braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). Финальный image содержит
статические файлы и Nginx, без Node runtime.
## Поддержка содержания и иллюстраций

Руководство сверено с кодом Asmy 3.7.1 и описывает его фактические ограничения.
Изменения следует сверять с кодом manager и локальным запуском, особенно для
ролей, установки, обновления, удаления данных и авторизации. Не переносить
в пользовательское руководство обещания из TODO или планы будущих функций.
Агент, который добавляет возможности или меняет пользовательское поведение
Asmy, обязан актуализировать соответствующие статьи после приёмки решения
Александром, как часть завершения задачи. Промежуточные варианты разработки
и интерфейса в руководство не переносить. Скриншоты нужны там, где они помогают
понять действие; добавлять их ради количества не требуется.

Разделы разделены по задачам: начало работы, проекты и доступ, Docker,
хранилища и файлы, обслуживание. Предпочитать отдельные связанные главы для
самостоятельных задач, а не накапливать всё в больших страницах: объём
документации может расти, если навигация остаётся понятной и последовательной.
Существующие публичные адреса статей
`/getting-started`, `/getting-started/opportunities`, `/getting-started/installing`,
`/usage/constructor`, `/usage/manual-block`, `/usage/roles`, `/usage/updating`
сохраняются при перестановке числовых префиксов файлов. Проверять не только
сборку, но и навигацию, поиск, внутренние ссылки и якоря в готовом static output.

Иллюстрации в `public/images/*.jpg` — настоящие снимки интерфейса на отдельном
демонстрационном окружении. Проект Lumen, домены `example.com`, контейнеры и
файлы не связаны с production. Имена и содержимое допустимо подготавливать
специально для примера; элементы интерфейса, состояние и возможности должны
оставаться достоверными. Нейрогенерация допустима только при сохранении этой
точности, но для текущих снимков не использовалась. Предпочитать несколько
полезных иллюстраций, а не снимок каждого экрана. Перед добавлением проверить
изображение на секреты и персональные данные, обновить alt-текст и удалить
старый ресурс, если у него больше нет потребителей.

Известный дефект текущей цепочки Docus/Content/Shiki: в отдельных поисковых
фрагментах после блока кода может отображаться CSS подсветки. Поиск и переход
к статье работают; сам текст статьи отображается нормально. При следующем
обновлении темы проверить upstream-исправление, не добавляя отдельный поисковый
слой ради обхода.

## CI

Deploy запускается при push в main, кроме изменений только README.md/AGENTS.md.
Сборка читает и обновляет registry cache
`ghcr.io/<github.repository>/build-cache:docs` через штатный GITHUB_TOKEN.
Cache package оставлять private: промежуточные слои включают исходники.
Это фиксированный cache ref, не артефакт на каждый commit. При отсутствии кеша
выполняется обычная сборка; его необязательный export не блокирует deploy.
Build job имеет packages:write, deploy — только packages:read.
Неиспользуемые `.dockerbuild` artifacts отключены; журналы сборки сохраняются.
