## Сеть server

Для обратного проксирования Caddy должен видеть приложение в общей Docker-сети **`server`**. Установщик создаёт её как attachable overlay и при необходимости включает Swarm, в том числе при Compose-развёртывании Asmy.

Подключайте web-сервис в исходном файле развёртывания:

```yaml
services:
  web:
    # Образ, volumes и остальные параметры вашего приложения.
    networks:
      - server

networks:
  server:
    external: true
```

Это фрагмент существующего Compose-файла, не самостоятельная конфигурация. Полный пример — в [настройке домена](/usage/constructor).

Не подключайте все компоненты без необходимости. Например, БД может оставаться в закрытой сети приложения, а web-контейнер — одновременно в закрытой сети и `server`.

## Имя и порт

В поле Alias домена укажите имя, которое разрешается из сети Caddy. Для Compose это может быть заданное `container_name`, для Swarm — устойчивое имя сервиса. Не используйте `localhost`: для Caddy это он сам.

Указывайте внутренний порт приложения. Например, при публикации `8080:3000` Caddy обычно должен обращаться к контейнеру на `3000`, а не к хосту на `8080`.

Если сайт отвечает 502, проверьте:

1. Контейнер запущен и приложение слушает нужный порт.
2. Caddy и приложение действительно подключены к `server`.
3. Alias соответствует доступному в этой сети имени.
4. Процесс слушает не только loopback-интерфейс внутри контейнера.

Не удаляйте рабочую сеть для исправления такой ошибки. Команды безопасной диагностики — [в разделе решения проблем](/operations/troubleshooting).
