## Логи

На карточке контейнера нажмите **«Логи»**, на карточке Swarm-сервиса —
**«Логи сервиса»**. Здесь отображаются stdout и stderr процесса. У сервиса
объединяются доступные журналы его задач, рядом со строками указаны источники.
Если приложение пишет только в файл, этот файл не появится в Docker-логах автоматически.

Новые записи поступают автоматически. Для просмотра истории прокручивайте вверх:
панель подгружает старые строки по мере необходимости. Вся история не помещается
одновременно в страницу, поэтому большой журнал не требует отрисовки тысяч
строк сразу. Кнопка со стрелкой внизу справа возвращает к новым записям.
Пока вы читаете историю, новые записи не уводят прокрутку вниз.

В шапке есть индикатор связи. Если часть истории недоступна или чтение прервано,
появляется значок предупреждения; наведите на него указатель, чтобы увидеть
причину. Уже прочитанные строки остаются на экране. Docker может удалить старую
задачу вместе с её журналом — Asmy не восстанавливает удалённые Docker-логи.

Наличие истории зависит от logging driver и его ротации. Для контейнера с TTY
время отдельной записи может отсутствовать; содержимое вывода сохраняется.

Ищите исходную ошибку запуска, подключения к БД или чтения настроек. Не считайте отсутствие новых строк доказательством исправности: приложение может не вести подробный вывод.

Логи могут содержать токены, email, строки подключения и персональные данные. Перед отправкой коллеге или в поддержку удалите чувствительные значения. Не публикуйте целиком Docker inspect: в нём могут быть переменные окружения с секретами.

## Терминал

Для работающего контейнера, когда это позволяет интерфейс, доступна кнопка **«Открыть терминал»**. Она открывает shell **внутри выбранного контейнера**, а не SSH-сеанс на сервере.

Для первой проверки достаточно безопасных команд:

```sh
pwd
ls
```

Доступные утилиты и пути зависят от образа. В минимальном образе может не быть `bash`, пакетного менеджера и других привычных программ. Терминал не создаёт их автоматически.

Команды выполняются с правами пользователя Docker exec; в некоторых образах это root. Изменения в подключённом volume затрагивают реальные данные приложения. Изменения только внутри слоя контейнера могут исчезнуть при пересоздании.

## Если соединение не устанавливается

- Убедитесь, что контейнер работает и в нём есть оболочка.
- Проверьте, что сессия Asmy ещё действительна.
- Если перед панелью есть другой reverse proxy, он должен пропускать WebSocket.
- После выхода или смены пароля терминал старой сессии закрывается; войдите заново и откройте новое подключение.

Закрытие вкладки терминала не заменяет остановку приложения и не гарантирует завершение всех процессов, которые вы успели запустить внутри контейнера. Для долгоживущих процессов используйте конфигурацию приложения, а не ручной запуск через web-терминал.
