## Что подготовить

- Linux-сервер и терминал с правом управлять Docker. Установщик рассчитан на обычный Docker Engine с локальным socket и каталогом `/var/lib/docker`.
- Работающий Docker Engine и плагин Docker Compose. Нижняя граница совместимости Docker API — Engine 19.03 / API 1.40; для новой установки используйте поддерживаемую версию Docker.
- Домен для панели, например `admin.example.com`, и DNS-запись на адрес сервера.
- Доступ сервера к `asmy.pro` и реестрам образов для ночной проверки и загрузки релизов. `raw.asmy.pro` ещё нужен при переходе со старого updater.
- Свободные **80/TCP и 443/TCP** для Caddy. Конфигурация также публикует UDP-порты 80 и 443. Если на сервере уже работает другой web-сервер, сначала спланируйте перенос: Asmy не настроит совместное использование занятых портов.

Если у домена есть и A-, и AAAA-записи, обе должны указывать на доступный сервер. DNS для `www` и дополнительных доменов настраивается отдельно.

Инструкции по установке Docker для своей ОС смотрите в [официальной документации Docker](https://docs.docker.com/engine/install/).

Asmy получает расширенные привилегии, Docker socket, данные Docker и доступ к корню хоста. Не устанавливайте его в окружение, где такой доступ неприемлем. Rootless Docker, нестандартный Docker data-root и многоузловой кластер требуют отдельной проверки; руководство не обещает их автоматическую настройку.

## Запустите установщик

Команды выполняются **на сервере**, а не на компьютере, с которого вы будете открывать панель. Войдите по SSH под root либо в подходящую административную оболочку.

Установочная папка на сервере не нужна. Установщик работает в отдельном
Docker-контейнере; команду можно выполнять из любой директории.
Выберите опубликованный релиз и подставьте его номер вместо `4.1.0` в примере:

```bash
ASMY_VERSION=4.1.0
docker pull "alexbidenko/admire-server-manager-installer:$ASMY_VERSION"
docker run -it --name admire-server-manager-installer \
  --label pro.asmy.role=installer \
  --log-driver json-file --log-opt max-size=5m --log-opt max-file=1 \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  "alexbidenko/admire-server-manager-installer:$ASMY_VERSION"
```

Версионный образ по умолчанию устанавливает соответствующий релиз Asmy.
Установщик получает доступ к Docker socket и может управлять сервером через
Docker. Используйте официальный образ.

Контейнер последней операции сохраняется после завершения: в нём остаются
параметры и журнал. Это позволяет разобраться с ошибкой и повторить ту же
операцию. Для повторного запуска после устранения причины:

```bash
docker start -ai admire-server-manager-installer
```

Не запускайте вторую установку поверх работающего установщика. Для обновления
уже установленной панели используйте [штатный механизм](/usage/updating).

## Ответьте на вопросы

| Параметр | Что указать |
| --- | --- |
| Email | Действующий email для сертификатов и первого административного аккаунта. |
| Адрес Asmy | Имя хоста, например `admin.example.com`, без `https://`, пути и завершающего `/`. |
| Режим Docker | Compose для запуска через Docker Compose либо Swarm для запуска сервисами Swarm. |
| HTTPS | Для публичной панели выбирайте HTTPS. DNS и доступность сервера должны быть подготовлены заранее. |

Выбранный режим не переносит ваши уже запущенные приложения между Compose и Swarm.

### Почему Swarm включается и в режиме Compose

Asmy использует общую сеть `server` типа **overlay с `--attachable`**. Она подходит и сервисам Swarm, и отдельным контейнерам Compose, но требует включённого Swarm. Установщик инициализирует Swarm, если он выключен. Сам Asmy при выборе Compose продолжает запускаться через Compose.

Уже активный кластер и существующая сеть не пересоздаются. Установка в существующий кластер требует подходящего manager-узла. Не удаляйте сеть `server` у работающей установки.

Если Docker не может выбрать адрес из нескольких интерфейсов, определите правильный адрес сервера и выполните:

```bash
docker swarm init --advertise-addr <IP-или-интерфейс>
```

Затем повторите установку. Не выполняйте `swarm leave` или повторную инициализацию активного кластера для обхода ошибки. Требования к межузловым портам описаны у [Docker](https://docs.docker.com/engine/network/drivers/overlay/); не открывайте их в интернет без необходимости.

## Проверьте результат

1. Убедитесь, что установщик завершился без ошибки.
2. Откройте `https://admin.example.com` со своим адресом.
3. Выполните [первый вход и смену пароля](/getting-started/first-login).
4. Проверьте разделы «Контейнеры» и «Хранилища». В них будут и служебные ресурсы самой панели.

Успешный запуск Docker ещё не означает, что DNS, сертификат и Caddy уже готовы. Если панель не открылась, начните с [диагностики](/operations/troubleshooting).

При ошибке обязательного этапа установщик останавливается. Сохраните исходный текст ошибки и проверьте состояние Docker перед повтором. Не удаляйте volumes и БД, пытаясь начать установку заново.

## Где находятся данные

Скрипты, `.env` и Compose-файлы установщика находятся внутри его контейнера.
Каталоги в `/root`, `/opt` или текущей директории для работы Asmy не требуются.
Docker хранит свои образы, журналы и volumes обычным способом; автоматической
очистки посторонних образов или volumes установщик не выполняет.

Панель использует SQLite на локальном volume `admire-server-manager_data`.
Ежедневные копии — в отдельном volume `admire-server-manager_backups`.
PostgreSQL для новой установки не требуется. В Swarm панель и Caddy закреплены
на одном управляющем узле; многоузловое распределение и автоматический перенос
данных сейчас не поддерживаются. Подробности — в [резервных копиях](/operations/backups).
