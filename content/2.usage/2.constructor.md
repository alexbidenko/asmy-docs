Эта глава описывает домен для HTTP/HTTPS-сайта. Для TURN и других TCP-протоколов с TLS используйте [«TCP с TLS»](/usage/tcp-tls). Добавление домена в панели не создаёт DNS-запись и не запускает приложение.

При сохранении применяются настройки выбранного режима. Неприменимые поля
очищаются: например, при сохранении редиректа прежние Alias, порт и настройки
тестовых поддоменов больше не используются. Само переключение режима до
сохранения не стирает введённый текст.

## Пример: сайт Lumen

Пусть приложение доступно внутри контейнера `lumen-web` на порту `80`, а посетители должны открывать `https://lumen.example.com`.

### 1. Подключите приложение к сети

Caddy и приложение должны находиться в общей Docker-сети `server`. Для Compose можно использовать такой пример:

```yaml
services:
  web:
    image: nginx:stable-alpine
    container_name: lumen-web
    restart: unless-stopped
    volumes:
      - content:/usr/share/nginx/html:ro
    networks:
      - server

volumes:
  content:

networks:
  server:
    external: true
```

Это пример web-сервера со статическими файлами. Для собственного приложения замените образ, команду и подключение данных. Запустите его обычным для проекта способом, например `docker compose up -d` из каталога с Compose-файлом.

Публиковать порт контейнера на хост через `ports` для Caddy не требуется. В форме нужен **внутренний порт приложения**, а не внешний порт хоста. Процесс должен слушать сетевой интерфейс контейнера, а не только `127.0.0.1`.

### 2. Настройте DNS

Создайте DNS-запись `lumen.example.com` на адрес сервера. Убедитесь, что сервер доступен извне по HTTP/HTTPS и запросы приходят в Caddy.

### 3. Добавьте домен

Откройте проект → вкладку **«Домены»** → карточку с плюсом → **«Добавить домен»**.

| Поле | Значение в примере |
| --- | --- |
| Протокол | `https://` |
| Hostname | `lumen.example.com` |
| Режим работы | Обратный прокси |
| Alias | `lumen-web` |
| Порт | `80` |

![Настройки обратного прокси для Lumen](/images/domain.jpg)

Alias — имя, доступное из сети Caddy, без протокола и порта. Для Swarm укажите разрешаемое в общей сети имя сервиса; имя отдельной задачи Swarm нестабильно.

### 4. Примените и проверьте

Нажмите «Сохранить» и выберите применение конфигурации. Откройте сайт по домену и проверьте нужную страницу. Если видите 502, начните с имени контейнера, порта и сети, а не с повторной выдачи сертификата.

## Сохранение и применение

После сохранения Asmy предлагает два действия:

- **«Сохранить»** — записать настройки в БД без немедленного применения.
- **«Перезагрузить»** — сохранить и запустить обновление конфигурации Caddy.

Отложенные изменения можно применить кнопкой **«Перезапустить»** в разделе «Проекты». Применяется общая конфигурация web-сервера, поэтому изменения могут затронуть и другие сайты.

Asmy сначала собирает и проверяет новую конфигурацию, сохраняя работающий Caddy. При ошибке проверки он не заменяется. Успешный ответ применения означает, что новый Caddy запущен и ответил на проверку готовности; выдача сертификатов и доступность приложений проверяются отдельно. При ошибке запуска Asmy пытается восстановить прежний образ и необходимые ему права/подключения хранилищ и сообщает результат. Настройки в БД при этом не откатываются: исправьте их перед повторным применением.

Применение продолжается на сервере независимо от открытого HTTP-соединения.
Если Caddy при замене кратко оборвёт связь, открытая вкладка дождётся её
восстановления и получит итог операции. Не нажимайте применение повторно из-за
краткого обрыва. Успех появляется после проверки готовности Caddy, а не сразу
после отправки запроса. При перезапуске самой панели неподтверждённая операция
сообщает об ошибке: сначала проверьте сайты и логи, затем решайте о повторе.
После перезагрузки вкладки прежнее ожидание не восстанавливается автоматически.

Проверьте сайт и при ошибке [логи Caddy](/operations/troubleshooting). Caddy при применении может пересоздаваться, поэтому отсутствие перерыва в соединениях не гарантируется.

## Дополнительные настройки

- **Запрет индексировать** добавляет `X-Robots-Tag: noindex,nofollow`. Это указание поисковикам, а не защита данных.
- **websocket** включает соответствующую настройку проксирования. Для приложения с WebSocket проверьте соединение после применения.
- **Тестовые поддомены** — экспериментальный сценарий. Условия и ограничения вынесены [в отдельную главу](/usage/test-subdomains).

Для `www` нет специального переключателя: при необходимости добавьте отдельный домен и выберите [режим «Редирект»](/usage/proxy-settings#редирект). Для каждого дополнительного имени нужна собственная DNS-запись. Ранее включённые автоматические www-редиректы удалены; отдельные домены вместо них не создаются.

Другие режимы, заголовки и парольная защита описаны в [«Проксирование и защита сайта»](/usage/proxy-settings).
