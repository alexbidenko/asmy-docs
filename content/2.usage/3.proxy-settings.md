Основной сценарий обратного прокси разобран в [главе о доменах](/usage/constructor). Здесь — остальные настройки той же формы.

Для протоколов вне HTTP, например TURN/TLS, предусмотрен [режим TCP с TLS](/usage/tcp-tls).

## Редирект

Режим **«Редирект»** отвечает перенаправлением браузера на указанный адрес. В адресной строке посетителя будет новый URL.

Например, `old.example.com` можно перенаправлять на `https://lumen.example.com`. Выберите режим «Редирект», укажите протокол и адрес назначения, затем тип:

| Тип редиректа | Когда выбирать |
| --- | --- |
| Временный (302) | Адрес назначения может измениться. Выбран по умолчанию. |
| Постоянный (301) | Переезд окончательный. Браузеры и поисковые системы могут запомнить новый адрес. |

У существующих редиректов сохраняется прежний код 302. Редирект направляет посетителя строго на указанный адрес: исходные путь и параметры запроса автоматически не добавляются. Например, при назначении `https://lumen.example.com` запрос `old.example.com/catalog?id=1` приведёт на главную `https://lumen.example.com`. Если нужно отдельное правило переноса пути, используйте [ручную настройку](/usage/manual-block).

Для перенаправления `www` добавьте его как отдельный домен, настройте для него DNS и выберите режим «Редирект». Другие варианты имени автоматически не создаются. После сохранения [примените конфигурацию](/usage/constructor#сохранение-и-применение) и проверьте результат для главной страницы, вложенного пути и параметров запроса.

В адрес назначения можно вставить полный `http://` или `https://` URL — кнопка
протокола подстроится, повторный префикс не добавляется. Переключение протокола
меняет только начало адреса; путь, параметры, fragment и вложенные URL сохраняются.
При переходе на 4.3.2 редкие старые записи с несколькими HTTP-префиксами исправляются
автоматически: сохраняется внешний протокол. Слэши внутри пути не удаляются.

## Проксирование внешнего сайта

Режим **«Проксирование»** получает ответ другого HTTP/HTTPS-сервера через Caddy. Посетитель остаётся на вашем домене; браузер не перенаправляется, как при редиректе. В коде Asmy этот режим называется `forward_proxy`, но он не настраивает универсальный прокси-сервер для браузера.

Укажите протокол и адрес назначения. Caddy передаёт upstream его собственный Host. Абсолютные ссылки, cookies, редиректы и политика безопасности исходного сайта могут быть привязаны к его домену — Asmy не переписывает их автоматически. Проксируйте только сервисы, которые вы контролируете или имеете право использовать таким способом.

## Заголовки ответа

На вкладке **«Заголовки»** добавьте пары ключ/значение. Они применяются в направлении **от сервера к клиенту**.

Например, для ресурса, который должен открываться только с того же сайта, можно задать `Cross-Origin-Resource-Policy: same-origin`, если это соответствует устройству приложения. Сначала проверьте интеграции: универсального набора заголовков, подходящего всем сайтам, нет.

Старое описание обработки всех `OPTIONS` кодом 204 больше не соответствует текущему конструктору. Он не решает CORS автоматически. Разрешённые origins, методы и credentials нужно согласованно настроить в приложении или Caddy; одного успешного preflight недостаточно.

## Web-авторизация

На вкладке **«Авторизация»** можно включить **«Включить web-авторизацию»** и задать логин и пароль. Это Basic Auth на уровне Caddy перед сайтом, отдельный от аккаунтов Asmy.

Используйте его вместе с HTTPS. Он подходит, например, для закрытого тестового сайта, но не заменяет полноценную авторизацию приложения. Настройка также применяется к тестовым поддоменам этого домена.

На домене-редиректе включённая защита проверяется перед перенаправлением:
без правильных реквизитов посетитель получает запрос авторизации, после входа —
редирект на настроенный адрес. Если защита выключена, редирект выполняется сразу.

При создании защиты укажите новый уникальный пароль. При редактировании пустое поле пароля сохраняет действующий пароль, а пустое
поле логина — действующий логин. Чтобы снять защиту, явно выключите переключатель.
При первом включении без логина или пароля защита останется выключенной. Не размещайте пароль в URL и не используйте пароль администратора Asmy.

После сохранения [примените конфигурацию](/usage/constructor#сохранение-и-применение) и проверьте сайт в отдельном приватном окне, где браузер ещё не запомнил Basic Auth.
